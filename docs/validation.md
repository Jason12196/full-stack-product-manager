# 验证说明

## 实际执行的包检查

- 主 skill 与四个内部模块的名称、描述及目录一致性。
- 主入口引用的四个模块与模板在单独复制安装后仍可读取。
- 仓库文档的相对链接和 HTML 媒体路径。
- 不绑定作者个人绝对路径。
- 中文显示名、显式调用名与自动发现策略。
- SVG 横幅 XML 可解析；GitHub README 渲染另作页面检查。

运行：`python3 scripts/validate.py`。只用 Python 标准库，不安装依赖，不修改用户的真实 skill 目录；临时安装副本自动清理。

## 场景桌面审查

这些是对规则的人工推演，不是独立 agent 的实际行为测试。

| 场景 | 应采取的入口和行为 | 禁止行为 |
|---|---|---|
| 新功能且需求含糊 | 需求与竞品，拆功能并给对应证据，按需进入方案 | 先写产品代码再补需求 |
| 明确后端功能 | 功能方案，核实已有实现，图与具体代码清单，待确认 | 强制制作 UI 或全行业报告 |
| 隔离交互展示 | 交互方案，说明模拟与隔离，确认后创建 | 未确认创建 demo、改主路由或接生产写接口 |
| 用户说“帮我修” | 只读诊断、修复方案与图、待确认 | 将任务请求当作尚未展示方案的批准 |
| 实现中发现新 bug | 记录问题并提交修复方案，等确认 | 以原功能方案的批准为由顺手修 |
| 确认 v2 | 核实 v2 范围，进入实现与验收 | 重复请求批准既定步骤 |
| 验证失败且改变根因假设 | 分析证据、更新方案并重新确认 | 反复叠加补丁 |
| 同一问题连续 3 轮失败 | 停止写入、重审根因/架构、提交新方案 | 无讨论地进入第 4 轮 |
| 已批准的恢复条件满足 | 核实回退范围，执行、计轮次、验证 | 重置无关工作或运行未授权生产操作 |
| 只读解释 | 读取相关实现并回答，报告代码无 | 创建状态文件、修改代码或强制调研 |
| 上下文压缩后继续 | 恢复功能、批准范围、轮次、验证和遗留 | 默认批准或把累计轮次重置为零 |
| 不具备竞品浏览能力 | 标明限制与未验证证据 | 编造亲测结果或完全还原结论 |

## 仍需真实使用验证

- 在不同模型与客户端上的自动发现成功率。
- 长会话里实际遵守确认点、轮次和遗留问题跟踪的能力。
- 真实项目里交互展示的隔离性与技术方案质量。
- 各项目真实正常、失败、恢复场景的验收效果。

文档规则和结构校验不构成程序级强制控制。项目自身的权限、沙箱、发布审核与数据库保护仍由环境负责。
