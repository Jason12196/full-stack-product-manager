# 交互方案

继承主 skill 的确认、状态与修 bug 流程。目标是可对照、可操作的单个功能展示，不默认制作整套产品原型。

## 先检查

读取功能映射、竞品对应行为和已有 UI。核实组件库、设计 token、共享样式、状态管理、路由及可复用交互。与功能模块共用状态、接口与错误定义；若先做展示，标记暂定契约。

## 展示的范围与隔离

- 以功能 ID 为单位；必要时包含完成该功能必需的连续步骤。
- 还原可验证的布局、颜色、尺寸、文案、点击行为、状态与反馈；截图只有静态证据，不能证明点击行为。
- 确保核心控件可点击，支持复位、重复体验、关键异常状态切换。用模拟数据时明示“模拟”，不假装已连真实服务。
- 优先使用已有 sandbox、Storybook 或独立 demo 入口。没有时提出最小隔离方案；不得未经确认引入新工具链。
- 不接生产写接口，不改变主产品路由或数据；需要接真实服务时单独说明授权范围。保持样式作用域隔离，避免全局污染。
- 原样使用竞品商标、图片等素材前检查使用条件；不具备素材时采用标明的替代内容，不宣称完全一致。

## 提交方案，再等确认

方案说明：功能 ID 与来源、展示范围、已观察/未观察行为、界面与状态清单、组件层级、现有复用、新增内容、样式作用域、模拟与真实边界、具体文件、验证方法。

必须给交互流程图：点击/键盘入口 → 状态变化 → 用户反馈 → 恢复或退出；绿色正常，橙色恢复/降级，红色报错。同步写用户可见文案与焦点行为。没有回退时说明无回退。

展示代码也是代码，方案未经确认前不创建它。确认后由实现与验收模块落地，可先交付展示让用户比较，再提交或确认正式集成范围；展示批准不等于集成批准。

## 组件与功能协作

按责任和实际复用拆组件，不为一个小功能增加空泛抽象。组件清单至少区分容器、状态逻辑、可复用呈现和样式来源。优先用现有 token 和组件，避免复制出另一套相同样式。

接口/状态改变时同步功能方案；影响批准行为就重新确认。对照展示的每个状态都应能追到需求或已标明的假设。

## 验收移交

提供可访问的展示入口、对应竞品链接、对照步骤、模拟条件和未还原项。验收关注可点击行为、键盘操作、加载/空/失败/恢复、适用屏幕尺寸以及隔离是否真实成立。仅构建成功不算交互验收。

## 可维护性与修改前检查

展示或正式 UI 代码每轮写入前执行主 skill 的当前分支同步检查；有更新则安全同步并 review 引入变化，重新核实组件与样式复用。沿用项目组件模式、设计 token、命名和样式作用域，明确状态所有权、呈现/业务职责与接口边界。避免复制样式、巨型组件、分散魔法值、全局污染与仅为抽象而拆分。说明下一次同类交互变更的位置，保证隔离展示能在确认后合理复用或集成，不制造第二套长期维护的 UI。
